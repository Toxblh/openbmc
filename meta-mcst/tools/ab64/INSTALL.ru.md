# Прошивка REIMU A/B для BMC материнской платы 1E8CB-uATX (Эльбрус-8СВ)

Версия `@VERSION@`, ядро Linux 6.18, плата REIMU-5564 (AST2500, флеш 64 МиБ).
Неофициальная сборка на основе REIMU 1.0.2. Исходники: <https://github.com/Toxblh/openbmc>, тег `@VERSION@`.

Что появляется: два слота A/B с автоматическим откатом, управление вентиляторами, защита от перегрева, журнал событий, новый веб-интерфейс, агент хоста.

## Прочитайте перед установкой

**Прошивка BMC на свой страх и риск.** Она проверена на **одной** плате. На вашей может быть другая ревизия.

- **Нужен запасной путь.** Если прошивка не поднимется, спасают только SPI-программатор и консоль BMC (ttyS4, 115200). Без программатора отказ при записи может означать неработающий BMC.
- **Питание.** Отключение питания во время записи опасно. Самый опасный момент — откат на stock: там есть окно, когда загружаться не с чего.
- **Перезагрузка BMC жёстко сбрасывает хост.** Поэтому хост на время установки выключен.
- **Что не трогается:** U-Boot и флеш ПНС.
- **Что не переносится:**
  - сетевые настройки BMC: после установки он получает адрес по DHCP (MAC прежний, так что резервирование на роутере продолжит работать);
  - пароль root: снова `0penBmc`, его стоит сменить, а BMC не выставлять в интернет.
- **Что переносится:** ключи SSH, сертификат веб-интерфейса, пользователи IPMI, состояния сервисов.

Без DHCP BMC через минуту берёт резервный адрес: `192.168.1.1/24` на `eth0`.

## Что нужно

- BMC на официальной прошивке **REIMU 1.0.2** (пакет проверяет это сам), пароль root известен.
- Компьютер в той же сети, **не сам этот Эльбрус**: хост будет выключен.
- `ssh` (OpenSSH 8.4 или новее) и `fdtput`:
  - Debian/Ubuntu: `apt install openssh-client device-tree-compiler`
  - macOS: `brew install dtc`

Установка выполнялась с macOS: на реальной плате и целиком из этого пакета в эмуляторе QEMU. На Linux скрипты должны работать так же, но там их не запускали.

## Установка

В примерах BMC на `192.168.1.100`, подставьте свой адрес. Все команды выполняйте из этой папки.

```sh
shasum -a 256 -c SHA256SUMS      # на Linux: sha256sum -c SHA256SUMS
export BMC=192.168.1.100
export SSHPASS='0penBmc'         # ваш пароль root, если меняли
```

### 1. Выключите хост и перезагрузите BMC

Завершите работу Эльбруса штатно и убедитесь, что он выключен. Затем:

```sh
ssh root@$BMC reboot
```

Подождите 2–3 минуты. Холодный старт нужен, чтобы BMC прочитал данные платформы и начал установку с чистого состояния.

### 2. Сделайте бэкап и проверку

```sh
./backup-stock.sh $BMC ./backup
```

Скрипт сохраняет весь флеш и сверяет его с платой. **Сохраните папку `backup` в надёжном месте**: это единственная копия ваших MAC-адресов и настроек.

Если он напечатал `STOP`, **не устанавливайте**. Чаще всего это значит, что U-Boot на вашей плате отличается от проверенного.

### 3. Попробуйте без записи

```sh
./reimu-ab-from-stock test $BMC reimu-ab-kexec.tar
ssh root@$BMC 'uname -r; cat /run/initramfs/reimu-ab'
```

Новая прошивка запускается из RAM, флеш только для чтения. Должно быть ядро `6.18...` и `state=ram`. Датчики тут не появятся: при выключенном хосте инструмент не передаёт дерево устройств, это нормально.

Если BMC не вернётся, сторожевой таймер сам сбросит его в старую прошивку через 15 минут. Заодно будет сброшен хост, но он выключен.

Верните stock и подождите 2–3 минуты:

```sh
ssh root@$BMC reboot
```

### 4. Запишите

```sh
./reimu-ab-from-stock install $BMC reimu-ab-kexec.tar reimu-ab.tar
```

Несколько минут, с запасом 10. **Не отключайте питание.** В конце должно быть `slot a: intact`, `slot b: intact` и `installed and verified`. Перезагрузки на этом этапе нет.

Проверьте ещё раз, отдельно:

```sh
ssh root@$BMC reimu-ab verify
```

Если хоть одна проверка не `intact`, **не перезагружайте**: новая прошивка работает из RAM, запись можно повторить.

### 5. Перезагрузите

```sh
ssh root@$BMC reboot
```

Через 2–3 минуты:

```sh
ssh root@$BMC 'reimu-ab status'
```

Должно быть `booted: kernel=a rofs=a state=ok`.

### 6. Включите хост и проверьте плату

Включите Эльбрус через веб-интерфейс `https://$BMC` или кнопкой. **Подождите ещё 2 минуты** и запустите проверку:

```sh
ssh root@$BMC 'sh -s' < board-check.sh
```

Нужно `0 failed`. Если падают только проверки FRU, подождите минуту и повторите: FRU читается после включения платформы.

### 7. Сразу подключите агент хоста

На странице BMC **«Хост» → «Подключить агент хоста»**, команду выполните в терминале Эльбруса (нужен `sudo`).

**Не пропускайте этот шаг, если вентиляторы GPU управляются через агент.** На проверенной плате без агента вентилятор видеокарты (RX 5700 XT, стоит перед IOHUB) останавливался, и IOHUB доходил до 86 °C на простое. С агентом было 56 °C. До подключения не нагружайте хост.

Температуры и кривые вентиляторов настроены под эту плату, корпус и видеокарту. Посмотрите на температуры под нагрузкой на своей машине.

## Если что-то пошло не так

**Не загружается один слот.** U-Boot после 3 неудачных загрузок сам переключается на другой слот.

**BMC остановился в приглашении `ast#`** (консоль ttyS4, 115200):

```
run reimu_boot_b
```

**Вернуть stock** (проверено в QEMU именно этими командами, на реальной плате не выполнялось). Хост выключен, питание стабильно:

```sh
ssh root@$BMC 'reimu-ab ram'
# подождите около минуты
ssh root@$BMC 'mkdir -p /tmp/stock'
for f in u-boot-env.bin kernel.bin rofs.bin rwfs.bin SHA256SUMS; do
    ssh root@$BMC "cat > /tmp/stock/$f" < backup/$f
done
ssh root@$BMC 'reimu-ab restore-stock /tmp/stock && reboot'
```

**Ничего не загружается.** Запишите программатором `backup/flash.bin` целиком.

## Известные проблемы

- Кнопка выключения: короткое нажатие и `GracefulShutdown` Simply Linux может обработать как suspend, и хост не выключится. Лечится настройкой `HandlePowerKey=poweroff` в `/etc/systemd/logind.conf`.
- После `ForceOff` хост однажды сам включился через секунду (1 раз из 3), причина неизвестна.
- Пока хост игнорирует кнопку выключения, журнал получает строку каждые 10 секунд.
- Установка агента один раз упала с несовпадением ключа: повторите её.
